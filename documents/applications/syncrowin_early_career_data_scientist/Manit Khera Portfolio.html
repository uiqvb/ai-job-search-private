Chapter 1. The robot that saves your clothes

Smart Clothesline Robot. Embedded Systems unit, awarded 93.
Arduino Nano, C++, Raspberry Pi, Python/Flask, MQTT
Follow the build: 1First demo→ 2Second demo→ 3Build write-up on Hackster.io→ 4Source code on GitHub

The idea. Clothes get rained on. So a small robot carries them between a sunny spot and a sheltered one, follows a line of black tape to get there, and turns to face the sun while it waits. I built and wired it myself: two wheels, three line sensors, two light sensors, one rain sensor and a cardboard body.

How I tested it. I got it wet. On purpose. Wetting the rain sensor sent it off to shelter, as it should. Then I lied to it: I fed it fake rain readings to check it would trust the weather forecast over a broken sensor. It did.

The real problem. The robot had a voltage problem I could not see. On fresh batteries it behaved perfectly. Once they dropped below about 90 percent, it started acting up. So I kept buying new ones, probably $100 worth, before I went back through the robot's logs. The boot ID and reset cause in each message showed it was browning out, and that led me to a faulty voltage converter.

I now own a large pile of batteries that are 90% full and useless to me

What I took from it. I should have checked the logs first. I now put fields like that into everything I build, because they are what made the fault findable.

Chapter 2. Giving it a brain it never asked for

Robot Controller API. Backend Development unit, awarded 100/100.
.NET 8, C#, PostgreSQL, Arduino C++, Docker, Jenkins
Follow the build: 1First demo, in class with my unit chair→ 2Open Day demo→ 3GitHub: first build, Open Day branch, deploying branch

The idea. A different unit entirely. I built a backend that does all the thinking, so a robot only has to ask "what next?" over Wi-Fi and do as it is told. Then I pointed it at the clothesline robot to see what would happen. For a while, not much: sometimes the backend worked and the robot ignored it, and sometimes the robot moved while the software believed something else entirely. So every command and result now goes into a PostgreSQL history I can query.

My favourite what-if. What if the Wi-Fi drops? A robot with no plan of its own would be lost. So I built for it before it ever happened: every command arrives with its own undo. After 7 seconds of silence the robot retraces its last five moves by itself, back toward signal, then tells the server what it did. The server checks that story in a simulation before believing it. When I tested it on the real robot, it ended up exactly where the server predicted.

Party trick. It is also an RC car. You can drive it from the dashboard with the WASD keys, like a video game. There is nothing fancy underneath: no special radio link, only ordinary web requests. The robot keeps asking the server "anything for me?" and the server answers.

Where it went. A first demo in class with my unit chair, then selected for Deakin Open Day, where I ran it live for prospective students and their parents.

Chapter 3. What if there were 5,000 of them?

Scaling the Robot Dispatch API. Distributed Programming unit.
C#, ASP.NET Core, PostgreSQL, Azure, Docker, NBomber, xUnit
Follow the build: 1Starting point: the Chapter 2 code→ 2Rebuilt code on GitHub→ 3Demo video→ 4Full report

The idea. One robot worked. So in a third unit I asked the uncomfortable question, built a pretend fleet in the cloud, and pointed it at my own backend. At 5,000 robots it completed zero jobs.

What I did about it. I went looking and found 12 problems, including one where two robots could grab the same job. I fixed them, taught the server to say "try again in a second" instead of falling over, added a second server, and ran it all again.

How I know it worked. 80 benchmark runs, each grid setup repeated three times with the median reported, plus 54 automated tests. Median claim time at 400 robots went from 766.5 ms to 59.5 ms.

Still unknown. The new breaking point. My pretend fleet gave up before the backend did, which I am choosing to take as a compliment.
